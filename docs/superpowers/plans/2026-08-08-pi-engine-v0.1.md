# PI-engine v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a theory-neutral observational/predictive engine that normalizes cases, applies explicit inspectable models, simulates trajectory ensembles, evaluates held-out outcomes, and preserves uncertainty and residuals.

**Architecture:** Use a hybrid state-space + graph representation backed by explicit Pydantic schemas. Route cases through a deterministic model registry, simulate deterministic/stochastic trajectories, then evaluate with temporal holdouts and calibration metrics. Keep higher-order invariant hypotheses and intervention logic outside v0.1 core.

**Tech Stack:** Python 3.12+, Pydantic v2, NumPy, SciPy, NetworkX, pandas, pytest, Hypothesis.

## Global Constraints

- v0.1 is observational/predictive only.
- Models must be explicit, inspectable, versioned, and provenance-bearing.
- No opaque learned router or ML framework in v0.1.
- State-space and graph views must reference the same canonical variables.
- Future outcome leakage across the prediction cutoff is a test failure.
- Competing models remain separately inspectable.
- Epistemic closure and causal closure must remain distinct.
- Unknown/structured residuals must be retained.
- Invariant hypotheses such as 4+3+1, 7+1, Space/Time/Geometry/Energy, etc. must never be required schema fields.
- Intervention structures may be reserved for compatibility but must not be executed, optimized, or ranked.

## Deferred Work

Do not implement in this plan:
- automatic cross-domain invariant discovery/promotion,
- learned model router/RMI,
- hypothetical intervention simulation/optimization,
- autonomous control/action,
- metaphysical interpretation layer,
- live ingestion/connectors,
- UI/dashboard beyond simple reports/CLI.

## Codex Handoff

Implementation should use an isolated worktree and follow TDD. Execute task-by-task with review gates. Preserve small commits so architectural discussions can continue while the theory-neutral substrate advances independently.
